# 🔄 Руководство по откатам - DeliveryMiniapp

## 📋 Обзор

Система откатов DeliveryMiniapp предоставляет полную безопасность с возможностью восстановления к любому стабильному состоянию. Это профессиональная архитектура с лучшими практиками DevOps.

## 🏗️ Архитектура безопасности

### 🔒 Многоуровневая защита

1. **Git версионирование** - полная история изменений
2. **Автоматические бэкапы** - перед каждым деплоем
3. **Health checks** - мониторинг состояния
4. **Rolling updates** - безопасные обновления
5. **Автоматические откаты** - при сбоях

### 📁 Структура сред

```
automation/
├── production/     # 🟢 Продакшн среда
├── staging/        # 🟡 Тестовая среда  
├── development/    # 🔵 Среда разработки
├── dashboard/      # 📊 Панель управления
└── backups/        # 💾 Резервные копии
```

## 🚀 Быстрый старт

### 1. Создание бэкапа

```bash
# Создать бэкап продакшн среды
./scripts/rollback.sh backup production

# Создать бэкап тестовой среды
./scripts/rollback.sh backup staging

# Создать бэкап среды разработки
./scripts/rollback.sh backup development
```

### 2. Просмотр доступных бэкапов

```bash
# Показать все бэкапы продакшн
./scripts/rollback.sh list production

# Показать все бэкапы тестовой среды
./scripts/rollback.sh list staging
```

### 3. Откат к бэкапу

```bash
# Откат к конкретному бэкапу
./scripts/rollback.sh rollback-backup production backup_production_20231201_143022

# Откат к git коммиту
./scripts/rollback.sh rollback-commit production abc1234
```

## 🔧 Детальное руководство

### 📦 Создание бэкапов

Бэкапы создаются автоматически перед каждым деплоем и вручную по команде.

**Что включается в бэкап:**
- ✅ База данных (delivery.db)
- ✅ Конфигурация (.env)
- ✅ Логи (logs/)
- ✅ Метаданные (manifest.json)

**Структура бэкапа:**
```
backups/
└── backup_production_20231201_143022/
    ├── delivery.db
    ├── .env
    ├── logs/
    └── manifest.json
```

### 🔄 Откат к бэкапу

1. **Автоматический бэкап** текущего состояния
2. **Остановка сервисов** для безопасного восстановления
3. **Восстановление** базы данных и конфигурации
4. **Запуск сервисов** с проверкой здоровья

### 🔗 Откат к git коммиту

1. **Создание бэкапа** текущего состояния
2. **Сохранение изменений** в git stash
3. **Переключение** на нужный коммит
4. **Восстановление** среды из бэкапа
5. **Запуск** с проверкой здоровья

## 🚨 Аварийное восстановление

### 🔥 Критический сбой

```bash
# 1. Немедленная остановка
pkill -f "node.*production"

# 2. Откат к последнему стабильному состоянию
./scripts/rollback.sh rollback-backup production $(ls -t backups/backup_production_* | head -1)

# 3. Проверка восстановления
curl -f http://localhost:3000/health
```

## 🔧 CI/CD интеграция

### GitHub Actions

```yaml
# Автоматический откат при сбое деплоя
- name: 🔄 Rollback on failure
  if: failure()
  run: |
    ./scripts/rollback.sh rollback-backup production latest
```

### Jenkins Pipeline

```groovy
// Автоматический откат в Jenkins
post {
    failure {
        sh './scripts/rollback.sh rollback-backup production latest'
    }
}
```

## 🔧 Устранение неполадок

### ❌ Частые проблемы

**Проблема:** Откат не выполняется
```bash
# Решение: Проверка прав доступа
chmod +x scripts/rollback.sh
sudo chown -R include:include backups/
```

**Проблема:** Бэкап поврежден
```bash
# Решение: Восстановление из git
git checkout HEAD~1 -- production/delivery.db
```

**Проблема:** Сервис не запускается
```bash
# Решение: Проверка конфигурации
./scripts/validate-config.sh production
```
